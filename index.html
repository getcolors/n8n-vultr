DEPLOYMENT · VULTR · SERVERLESS POSTGRES

n8n-vultr

Desired state for one self-hosted n8n server: the storage broker, the pageserver, one safekeeper and a Postgres 17 compute node on a single guarded Vultr instance in Amsterdam, with layers and WAL in Cloudflare R2.

The R2 prefix is the database. The tenant and timeline identities live in colors.yml and the data lives under this profile's prefix in R2, so a rebuilt host re-attaches the same identities and rehydrates — bounded by the async-WAL RPO. Ownership markers keep convergence from ever attaching a foreign or half-initialized prefix.

What is tracked here

colors.yml (the only editable desired state), the installed n8n Package Skill payload and lockfile, a root launcher copied from that payload, toolchain files, and documentation. Credentials live in gitignored .envrc.private; generated output in .colors/ is never committed.

Lifecycle

direnv allow               # once, after cloning
./green build              # render .colors/n8n-vultr/ — contacts nothing
./green create --dry-run   # walk the workflow, no side effects
./green create             # converge (requires authorization)
./green delete             # guarded and destructive

Connecting

No DNS record, no public database port — the firewall opens 22 only. The client path is the SSH tunnel through the alias the package writes:

ssh -L 55433:127.0.0.1:55433 n8n-vultr
psql 'postgresql://n8n@127.0.0.1:55433/n8ndb'

The role's password is generated on the server: ssh n8n-vultr cat /etc/n8n/secrets/n8n_role_password. n8n-status summarizes the deployment; n8n-rotate rotates the password atomically.

Live storage. Never configure R2 lifecycle rules on the bucket and never touch objects under n8n-vultr/data/ by hand — that prefix is live database storage, not backups.
